# 知识库操作手册

> 这份手册讲的是**怎么用**。为什么要这么装、装了哪些东西，见 [[知识库安装记录]]。
>
> 本库的选型依据见 [[Andrej Karpathy 的 LLM 知识库方法论]]，批次进度见 `wiki/index.md`。

## 一、日常节奏

知识库的运转分四种节奏，周期不同，别混在一起做。

| 节奏 | 频率 | 做什么 |
|------|------|--------|
| 收 | 随时 | 浏览器剪藏文章，落到 `EasyWebClipper/` |
| 判 | 攒够几篇 | 在 `wiki/index.md` 的批次表里逐篇判定 |
| 写 | 判定之后 | 把素材写成正文，或整合成概念 |
| 检 | 每月 | 找孤立页面、查矛盾、看连接度 |

## 二、收：剪藏

用浏览器里的 Easy Web Clipper 剪文章，自动落到 `EasyWebClipper/`。

这个目录是 raw 层，**只进不改**。原文在这里是唯一副本，不加工、不删改。判定时若认为某篇没有价值，也保留原文，只在批次表里标「仅存档」。

剪完顺手在 `inbox/README.md` 记一行：标题、日期、来源。不必当天判完，记下来是为了不忘。

不想手动记也可以——判定只认一个事实：文件有没有出现在 `wiki/index.md` 的批次表里。所以「哪些还没判」可以随时问脚本：

```
./scripts/clip-status.sh
```

它逐篇比对 `EasyWebClipper/` 与批次表，列出已判与待判，只读、不改任何文件。

## 三、判：四类判定

在 `wiki/index.md` 的批次表里逐篇判定，四选一。

| 判定 | 判断标准 | 落到哪 |
|------|---------|--------|
| 单列主题 | 有完整论证链，能独立成篇 | `01_` ～ `04_` 正文层 |
| 参考资料 | 价值在于被反复查阅，本身不构成主题 | `wiki/refs/` |
| 拆分取用 | 原文是合集，只有部分章节相关 | 切开放到对应正文 |
| 仅存档 | 与库的定位关系弱 | 留在 `EasyWebClipper/` |

判定的核心原则是**不为填目录而硬塞**。本库现有 121 篇 Markdown，其中 38 篇没有任何双链，这个数字已经偏高了。再多几篇无归属的，只会继续稀释结构。

不用自己盯着哪些没判。跑 `./scripts/clip-status.sh` 看台账，待判为 0 就说明这批清完了。攒够几篇再判，不必逐篇处理。

一个批次判完，开下一个批次号（002、003⋯⋯），在批次表里记一行。

## 四、写：正文由人写

**这是本库的底线。** 按这份周刊里「AI 与司机式知识」那条的说法，通过 AI 学习虽然快，但大脑没有参与反复思考，理解和记忆都不如传统方法。

所以 AI 在本库只做三件事：

- 起草摘要，落到 `wiki/summaries/`
- 起草概念文章，落到 `wiki/concepts/`
- 出可粘贴的草稿，落到 `wiki/落笔稿 - 批次 NNN.md`

正文由你改写定稿。草稿里标注「AI 起草」的提示，改写完就删。

## 五、怎么让 AI 干活

这几句话可以直接用。

- 「扫一遍 `EasyWebClipper/`，出判定表」——我会读原文、对照现有笔记、给四类判定
- 「这几篇出摘要」——落到 `wiki/summaries/`
- 「把某几篇整合成一个概念」——落到 `wiki/concepts/`
- 「出落笔稿」——我不改正文，只把草稿放 `wiki/落笔稿 - 批次 NNN.md`

## 六、检：每月健康检查

跑一次，四项。

1. **孤立页面**：没有入链也没有出链的笔记。目前的量是 38 篇，这是第一个该处理的
2. **矛盾内容**：同一个概念在不同笔记里说法不一致
3. **热门主题**：连接度最高的概念，往往值得单独成篇
4. **缺失主题**：反复被引用但还没写的笔记

## 七、备份

obsidian-git 每 10 分钟自动提交一次。但它**不会自动推送**（`autoPushInterval` 为 0），所以推到 GitHub 是手动动作。

若要全自动，可在 obsidian-git 设置里把推送间隔也设上。

## 八、故障处理

**文件莫名消失时，先别慌。** 用手写的正文都在 Git 里，找最近的提交就能恢复。

恢复步骤：

1. `git log --oneline` 找到内容还在的那个提交
2. `git reflog show master` 看有没有 `reset` 记录，能定位是什么时候、退到哪
3. 单个文件用 `git checkout <提交> -- <路径>` 取回

**已经发生过一次**：2026-09-29 有一次 `git reset --hard` 把 `wiki/`、`EasyWebClipper/` 从磁盘抹掉，提交对象还在，靠上面的办法全部恢复。原因未查明，此后若再遇到，值得查一下是 Obsidian 的 git 插件还是别的东西在跑 `reset`。

## 九、暂不做的部分

- **RAG 向量库**：正文规模仍在长上下文可覆盖范围内（估算约 58 万 token），先不引入。触发信号是：单次问答开始漏读笔记，或跨库检索变慢
- **模型微调**：属于方法论 §6.4 的 3～6 个月目标，数据量还不够
