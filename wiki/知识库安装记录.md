# 知识库安装记录

> 按《Andrej Karpathy 的 LLM 知识库方法论》§6.1 落地，记录本库装了哪些东西、为什么这么装。

## 一、采用的方案

采用**方案 A：Karpathy 原版（技术向）**，即 Obsidian 前端 + 长上下文问答 + 剪藏摄取。

不采用方案 B 的原因：本库是纯 Markdown 的 Git 仓库，已有 Obsidian、双链与 git 备份。
飞书多维表格会把知识搬出 Markdown，失去双链与版本历史。

## 二、目录结构

§6.1 的目录结构按本库现状做了映射，不照搬。

| 方法论里的目录 | 本库的对应位置 | 说明 |
|---------------|---------------|------|
| `raw/` | `EasyWebClipper/` | 剪藏原文只进不改 |
| `wiki/` | `wiki/` | AI 编译层，可删除重建 |
| `inbox/` | `inbox/` | 待判定素材的登记处 |
| `output/` | `output/` | 报告、幻灯片、可视化，不入库 |
| `scripts/` | `scripts/` | 自动化脚本 |

正文层沿用 `01_` ~ `04_` 四个板块，不改名。

## 三、已安装的组件

- **内置模板插件**：模板目录设为 `templates/`，可用「插入模板」命令调用
- **模板**：摘要模板、概念文章模板、索引模板
- **提示词**：`templates/prompts/知识编译提示词.md`
- **剪藏**：Easy Web Clipper 插件，落盘到 `EasyWebClipper/`
- **备份**：obsidian-git 每 10 分钟自动提交

## 四、日常流程

1. 浏览器剪藏文章，落到 `EasyWebClipper/`
2. 在 `wiki/index.md` 的批次表里判定四类：参考资料、单列主题、拆分取用、仅存档
3. 按判定结果落地到正文层或参考层
4. 有价值的原文补一篇摘要到 `wiki/summaries/`

## 五、暂不做的部分

- **RAG 向量库**：正文规模尚在长上下文可覆盖范围内，先不引入
- **模型微调**：属于 §6.4 的 3～6 个月目标，数据量还不够
