## 核心要点

1. **为什么值得看**：作者原话——「很多人说，不知道怎么写文档，都是凭着感觉写」，中文世界缺少可参照的文档规范，这「已经影响了中文软件的发展」。
2. **它是什么**：作者参考微软、MailChimp、Apple、Yahoo、Docker、Struts 等英文规范和维基百科的清单，结合自身实践整理的规范，正文托管在 GitHub 的 `ruanyf/document-style-guide`。
3. **六个分册**（原文只给链接，未含正文）：
   - 标题 / 文本 / 段落 / 数值 / 标点符号 / 章节结构
4. **原文性质**：这是一篇**导读**，真正的规范内容在 GitHub 仓库里，剪藏只拿到了目录。**拿这份剪藏当规范用是不够的**，需要另外获取六个分册正文。

## 建议去向

- **参考资料，不单独成篇**。它是一份「标准」，不是一篇「笔记」。
- **首选**：放入 `04_软件使用经验/` 下一个 `Writing/` 或 `技术写作/` 目录，作为长期查阅的规范条目。
- **进阶用法（推荐）**：把六个分册的关键条款提炼成一份**本库自用的检查清单**，挂到 `AGENTS.md` 里作为 AI 润色时的约束——这样它就变成了可执行的规则，而不只是参考资料。这也顺带解决了「78 个标签、行文风格不统一」这类问题的一部分。
